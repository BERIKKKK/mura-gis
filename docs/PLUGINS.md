# Плагиндер жүйесі — архитектура (ядро әзірлеушілеріне)

Плагин API-ін қолданушыға арналған сипаттама — [`plugin-sdk/`](../plugin-sdk/README.md) ([API](../plugin-sdk/docs/API.md),
[қауіпсіздік](../plugin-sdk/docs/SECURITY.md)). Бұл құжат — бағдарламаның ішкі құрылысы.

## Негізгі қағида

Ядро плагиндерге тәуелді емес. `main/plugins/` модулі жүктелмесе не қате берсе, `main.js` оны елемейді: «Плагиндер»
қойындысы мен кеңейту нүктелері жай ғана бос болады. Плагиндердің ешқайсысы бағдарлама іске қосылғанда орындалмайды —
интерфейс элементтері манифесттен (`contributes`) салынады, код пайдаланушы әрекетті таңдағанда ғана іске қосылады (lazy).

## Құрамы

```
plugin-sdk/lib/manifest.cjs   манифест келісімшарты: рұқсаттар, кеңейту нүктелері, үйлесімділік (бағдарлама мен SDK ортақ)
plugin-sdk/lib/zip.cjs        сенімсіз .muraplug архивін қатаң оқу; SDK үшін ZIP жазу
plugin-sdk/lib/geo.js         геометрия көмекшілері (плагин ортасында да, Node-та да)
plugin-sdk/lib/attrs.js       атрибуттарды схема бойынша сәйкестендіру/тексеру
plugin-sdk/lib/layers.cjs     жоба қабаттары → API пішімі (тек оқу, көшірме)
main/plugins/catalog.js       ұсынылған плагиндер: бағдарламамен бірге келетін үлгілер (plugin-sdk/examples/…)
main/plugins/manager.js       орнату (inspect → растау → install), күй, рұқсаттар, баптаулар, тұтастық, жою
main/plugins/host.js          оқшауланған процестер, mura-plugin:// протоколы, API брокері (рұқсат тексерісі)
main/plugins/runtime.js       плагин терезесіндегі `mura` нысаны (хабарлар арқылы)
main/plugins/sandbox-preload.js  плагинге берілетін жалғыз арна: send / onMessage
main/plugins/index.js         IPC mura:plugins-*, бағдарлама терезесіндегі UI сұраныстары
src/js/plugins-ui.js          «Баптаулар → Плагиндер», кеңейту нүктелері, плагин диалогтары/панельдері/қабаттары
src/css/plugins.css
```

Ядродағы өзгерістер аз: `main/main.js` (схема тіркеу, `setup()` — try/catch ішінде, «Файл → Плагиндер…»),
`main/preload.js` (`mura.plugins`), `src/js/project.js` («Плагиндер» қойындысы), `src/index.html` (скрипт пен стиль),
`src/qorgau/app.js` (`__qa.snapshot()` — ағымдағы аймақтың тек оқылатын көшірмесі). Қолданыстағы құралдар қайта жазылмады.

## Деректер (жобадан бөлек)

```
userData/plugins/installed/<id>/          плагин файлдары + .mura-integrity.json (әр файлдың SHA-256)
userData/plugins/state.json (+ .bak)      { suspended, plugins: { id: { enabled, granted, settings, version, sha256, installed_at, updated_at } } }
userData/plugins/data/<id>/storage.json   mura.storage (≤ 5 МБ)
```

Жоба файлы (`.gpkg`) плагиндер туралы ештеңе сақтамайды және плагинді жою оған тимейді. Жазу — `.tmp` → `rename`, алдыңғысы `.bak`.

## Ұсынылған плагиндер және мәртебе

`main/plugins/catalog.js` — бағдарламамен бірге келетін плагиндер тізімі (қазір: NIPD GeoJSON Exporter). Олар ядроға кірмейді:
«Плагин орнату → Ұсынылған плагиндер» бөлімінен пайдаланушы өзі орнатады, кәдімгі плагин сияқты оқшауланады, өшіріледі, жойылады.
Архив орнату кезінде бағдарламаның өз файлдарынан жиналады (желі керек емес). Мәртебе (`state.json` → `source`):
`official` — каталогтан орнатылған («Mura GIS әзірлеушісі»), `file` — файлдан («Тәуелсіз әзірлеуші»). Мәртебе манифесттегі
жазуға емес, орнату көзіне сүйенеді: ұсынылған плагиннің id-імен келген бөтен файл `file` болып қалады және ескерту шығады.
Каталогқа плагин қосу — `ENTRIES` тізіміне қалта қосу (плагин `plugin-sdk/examples/` ішінде, SDK құралдарымен тексерілген).
Релизде `.muraplug` файлы бөлек те жүктеледі (`.github/workflows/release.yml`).

## Ағындар

**Орнату.** Терезе `mura.plugins.inspect(file)` → `manager.inspect`: архив жадта оқылып тексеріледі, дискіге ештеңе жазылмайды,
жадта 15 минуттық `token` қалады → терезе тексеру нәтижесін, рұқсаттарды, жауапкершілік ескертуін көрсетеді → пайдаланушы
растаса `install(token, grants)`: файлдар уақытша қалтаға, хештер `.mura-integrity.json`-ға, қалта бір `rename`-мен орнына
(бар нұсқа — `.old-*` арқылы ауыстырылады, қатеде қалпына келтіріледі).

**Шақыру.** Батырма → `mura.plugins.invoke(id, command, ctx, selection)` → `host.invoke`: команда манифесттің сол нүктесінде
жарияланғаны тексеріледі → `activate` (тұтастық, үйлесімділік, жеке сессия, жасырын терезе, `mura-plugin://<id>/` хост беті) →
`invoke` хабары → плагин `mura.*` шақырады → `host.call` рұқсатты тексеріп деректі көшірме ретінде қайтарады не
UI/карта сұранысын бағдарлама терезесіне (`mura:plugins-ui`) жібереді → нәтиже.

**Тоқтату.** Өшіру, рұқсат өзгерісі, жою, жалпы тоқтату → `host.refresh()` процесті жояды; терезедегі плагин диалогтары,
панельдері, қабаттары `cleanup` арқылы алынады. Құлау / жауапсыздық (жүрек соғысы 15 с, `unresponsive`) — сол сияқты.

## 2.4.2 қосымшалары (Plugin API 1 ішінде, тек қосымша)

* `files.import` рұқсаты және `mura.files.open()` — `host.openFiles`: «Ашу» терезесі бағдарлама терезесіне байланады,
  плагинге `{ name, size, data }` (жолсыз) қайтарылады.
* `mark.suggest` кеңейту нүктесі: `src/js/plugins-ui.js` → `globalThis.MuraPluginSuggest.mark(snapshot)` барлық жарияланған
  командаларды шақырып, жауапты тазалайды (өрістер тізімі, ұзындық, тізім мәндері); `src/marks/marks.js` → белгі терезесіндегі
  «Плагин ұсынысы» өрісі. Таңдалған ұсыныс өрістерді толтырады, жазу — бұрынғыдай пайдаланушының «Сақтау» батырмасы арқылы
  (`mura://app/marks`). Ашық белгі плагинге `layers.cjs → selection({ layer: 'marks' })` арқылы көшірме болып беріледі.
* Ұсынылған плагин «Атау сәйкестендіргіш» (`plugin-sdk/examples/decree-matcher`): DOCX/PDF қаулыны өзі талдайды (ZIP, PDF
  құрылымы мен ToUnicode, кестені координаттан қалпына келтіру — сыртқы кітапханасыз), тізім плагиннің `mura.storage`-ында.

## Кеңейту нүктесін қосу

1. `plugin-sdk/lib/manifest.cjs` → `EXTENSION_POINTS` (тек соңына; бар атау өзгермейді).
2. `src/js/plugins-ui.js` → `paintPoints()`: элемент салу және `ctx` / `selection` беру.
3. Нүктеге жаңа контекст өрістері — тек қосымша. `plugin-sdk/docs/API.md`, `types/mura-plugin.d.ts`, `schema/manifest.schema.json` жаңарту.

## API-ге әдіс қосу

`host.js` → `call()` (рұқсатымен), `runtime.js` (плагин жағы), `plugin-sdk/tools/run.mjs` (жалған нұсқа), типтер мен API.md.
Бар әдістің мағынасын өзгерту — жаңа `apiVersion`. **Жоба деректерін жазатын әдіс** (`geometry.write`, `attributes.write`) қосылса:
пайдаланушыға өзгерістің айырмасын көрсетіп растату, жазу — иесінің протоколы арқылы (`mura://app/marks` т.б.), алдында `.bak` /
сақтық көшірме, қатеде кері қайтару — бұл бірінші кезеңде әдейі жасалмаған.

## Тексеру

`npm test` (`scripts/test-plugins.mjs`: манифест, архив шабуылдары, менеджер, геометрия, NIPD) және
`npm run smoke:plugins` (Electron: интерфейс арқылы орнату, NIPD экспорты, желі/файл/`mura://`/eval бұғаты, рұқсатсыз шақыру,
`.exe` сақтау, плагин қатесі мен шексіз цикл кезінде бағдарламаның жауап беруі, өшіру/жою).

Ескерту: сынақ ортасында (root, контейнер) Electron `--no-sandbox` арқылы іске қосылады — онда Chromium-ның ОЖ деңгейіндегі
sandbox-ы өшік, ал JS деңгейіндегі оқшаулау (Node жоқ, бөлек сессия, желі бұғаты, CSP) бәрібір тексеріледі. Пайдаланушы
компьютерінде (Windows) sandbox толық қосулы.

## Mobile / Android

Android нұсқасында плагин жүйесі жоқ және бұл кезеңде жасалмайды. Манифесттің `platforms` өрісі болашақ үшін: `desktop`
ғана бар плагин басқа платформада іске қосылмайды. Плагиндер жоба деректерін өзгертпейтіндіктен синхрондауға әсері жоқ.
