# «Жоспар», 3-кезең: жағдаят белгілері (ситуация) — ұсыныс

> **Мәртебесі: 6-бөлімнің үш кезеңі де іске асырылды** (нүктелік белгілер, барлық сызықтар, аудандар, жазу, қорғанның беті,
> жоспарға қосылатын «Өзге нысандар», жеке жоспардағы жағдаят, файлдан импорт, нүктелерден горизонтальдар). Код: `main/plans.js`
> (`FEAT_KINDS`, `SURFACES`, `cleanFeature`, `cleanObject.surface`, `cleanPlan.places`, `fsave` / `fdelete` / `fimport`), `main/gpkg.js`
> (`plan_features` қабаты), `src/plan/sheet.js` (белгілер, штрихтар, бетте салу, шартты белгілер), `src/plan/importer.js` (файлдарды оқу),
> `src/plan/crs.js` (координаттар жүйелері), `src/plan/tin.js` (Делоне, горизонтальдар), `src/plan/plan.js` («Жағдаят» мәзірі, картада
> сызу мен түзету, терезелер, панельдегі тізім). Тесттер: `scripts/test-plan.mjs`, `npm run smoke:plan`. Шешімдер — 7-бөлім.

Негіз: Ақтөбе облысы, Қарғалы ауданы ескерткіштерінің жоспарлары («Айтпайка-I қорымы», «Ақбұлақсай-I қорғаны»,
«Александровка-II қорғаны»). Бұл жоспарларда ескерткіштің нысандарынан басқа оның **жағдаяты** — жолдар, ЭБЖ, горизонтальдар,
ағаштар, егістік, бағдар нысандары, жазулар — салынған. Қазіргі «Жоспар» модулі мұның тек бір бөлігін (бағыттауышты) салады.

Қорытынды: жетіспейтіні — **нүктелік, сызықтық, аудандық жағдаят белгілері, жазулар** және қорғанның бетіндегі белгілер.
Бұлар ескерткіштің құрамына кірмейді: нөмірленбейді, экспликацияға түспейді — сондықтан `plan_objects`-ке емес, бөлек
қабатқа сақталуы керек (4-бөлім).

## 3. Белгілер анықтамалығы (бастапқы тізім)

Пішіндері — «Условные знаки для топографических планов масштабов 1:5000, 1:2000, 1:1000, 1:500» (ГУГК, 1989) негізінде,
жеңілдетілген; «Шартты белгілер» блогында әрдайым түсіндіріледі (2-кезеңдегі қағида). Кодтар латынша, тұрақты, жаңасы тек соңына.

**Нүктелік** (масштабтан тыс, ≈ 3–4 мм; жазуы сілтеме сызығымен не жанында):

| Код | ҚАЗ | РУС | Белгі |
|---|---|---|---|
| `tree` | Жеке ағаш | Отдельное дерево | ағаш белгісі |
| `trig` | Геодезиялық пункт | Пункт геодезической сети | үшбұрыш, ортасында нүкте |
| `tower` | Мұнара (байланыс) | Вышка (связи) | шаршы ішінде үшбұрыш |
| `pole` | Бағана, тірек | Столб, опора | толтырылған шеңбер |
| `well` | Құдық | Колодец | шеңбер ішінде нүкте |
| `spring` | Бұлақ | Родник | толқынды белгі |
| `building` | Құрылыс | Строение | толтырылған шаршы |
| `height` | Биіктік белгісі | Отметка высоты | нүкте + мән (мыс. «427,3») |
| `point` | Басқа бағдар | Иной ориентир | бос шеңбер |

**Сызықтық** (белгі сызықтың бойымен; жазуы — бойында, сызық бағытымен бұрылған):

| Код | ҚАЗ | РУС | Белгі |
|---|---|---|---|
| `road` | Асфальт жол | Автодорога с покрытием | қос тұтас сызық |
| `track` | Дала жолы | Грунтовая дорога | қос сызық, біреуі үзік |
| `path` | Соқпақ | Тропа | жіңішке үзік сызық |
| `power` | ЭБЖ | ЛЭП | сызық, әр төбеде тірек (нүкте) |
| `fence` | Қоршау, шарбақ | Ограждение | сызық + көлденең штрих |
| `ditch` | Арық, канал | Канава, канал | көк сызық |
| `river` | Өзен, жылға | Река, ручей | көк сызық, атауы |
| `ravine` | Жыра | Овраг | тісті сызық |
| `contour` | Горизонталь | Горизонталь | қоңыр сызық; мәні бойында, астында сызық үзіледі; 5 м сайын қалыңдатылған |
| `line` | Басқа сызық | Иная линия | жіңішке тұтас |

**Аудандық** (контур + штрих/толтыру + ортасында жазуы):

| Код | ҚАЗ | РУС | Белгі |
|---|---|---|---|
| `arable` | Егістік | Пашня | «═» штрихы (2-үлгідегідей) |
| `forest` | Орман, тоғай | Лес, роща | ағаш белгілерінің торы |
| `shrub` | Бұта | Кустарник | шағын шеңберлер |
| `swamp` | Батпақ | Болото | көк көлденең штрих |
| `water` | Су айдыны | Водоём | көк толтыру |
| `sand` | Құм | Пески | нүктелер |
| `area` | Басқа аудан | Иной участок | тек контур + жазуы (мыс. «ТҚҚ полигоны») |

**Жазу** (`text`): еркін мәтін, бұрылу бұрышы, өлшемі; қажет болса сілтеме сызығы нүктеге.

**Қорғанның бетіндегі белгі** — бөлек қабатқа емес, `plan_objects`-тің міндетті емес жаңа өрісі `surface` (тізім):
`stones` — тас үйінді (контур ішінде нүктелер), `pit` — ойық / тонау шұңқыры (ішкі шеңбер). Тек `kind = kurgan`-да; бос болса — `null`.
Іске асырғанда `trig` бұл тізімге қосылмады: қорғанның үстіндегі геодезиялық пункт — `trig` жағдаят белгісі, ол нысандардың үстінде
салынады (2-үлгідегідей), сондықтан бір нәрсені екі жерде сақтаудың қажеті жоқ.

**Мұртты қорған** — `plan_objects`-тің міндетті емес өрісі `mus`: тас жалдардың («мұрттардың») тізімі, әрқайсысы сынық сызық
`[[lat, lon]…]` (кемінде 2 бөлек төбе, ең көбі 8 мұрт). Тек `kind = kurgan`-да; жоқ болса — `null`. Жағдаят белгісі емес, нысанның бөлігі:
жеке жоспарда да салынады, қорғанмен бірге жылжиды, автоматты масштабқа әсер етеді. Бетте — контурлардың астында, жал бойымен тізілген
шағын ашық үшбұрыштар (≈ 1 мм, масштабтан тыс); «Шартты белгілер» блогында — «мұрт (тас жал)». Картада: «Сызу» мәзірі → «Мұрт (тас жал)»
не нысан терезесіндегі «Мұрт сызу»; төбелері «Контурды редакциялау» режимінде түзетіледі. GeoPackage-те `props` JSON-да сақталады
(геометрия бағанына кірмейді — QGIS-те тек қорғанның контуры көрінеді).

## 4. Деректер моделі (ұсыныс)

Жобаның жаңа қабаты **`plan_features`** (GeoPackage кестесі; ескі жоба ашылғанда жоқ болса — бос, ешнәрсе бұзылмайды):

```
{ id (16 hex), mark_id, cat ('point' | 'line' | 'area' | 'text'), kind (3-бөлімдегі код),
  name / name_ru (жазуы), value (сан: горизонтальдың не биіктік белгісінің мәні),
  lat, lon (нүкте, жазу), pts [[lat, lon]…] (сызық, аудан), rot (жазудың бұрышы, °),
  lbl [dx, dy] (жазудың ығысуы, мм — алдын ала қарауда сүйреу), src ({ layer, id } — В жолымен алынса, көшірме емес сілтеме),
  created_at/by, updated_at/by }
```

- Белгі ескерткішке `mark_id` арқылы байланысады (CLAUDE.md қағидасы); ескерткіштің атрибуттары көшірілмейді.
- Іске асырғанда міндетті: `main/plans.js` (немесе жаңа `main/plan-features.js`) → `clean()`-да барлық өріс; `main/gpkg.js` →
  жаңа кесте (геометрия түрі аралас: POINT / LINESTRING / POLYGON — gpkg жазушысы мұны қолдай ма, тексеру керек; болмаса үш кесте).
- GeoJSON экспортында `id`, `mura_id`, барлық атрибут сақталады.
- Синхрондау: қазір `plan_objects` те синхрондалмайды — `plan_features` та осы күйде қалады (бөлек шешім).
- Аудан — GeoPackage-те POLYGON (`pts` — тұйықталмаған сақина; кемінде 3 төбе, өзімен қиылыспайды).
- Жоспарға қосылған «Өзге нысандар» (2-бөлім, В жолы): `plans.places` — places қабатындағы id-лер тізімі (көшірме емес, атауы мен орны
  әр жолы places-тен алынады), `plans.place_lbl` — `{ id: [dx, dy] }` жазуының ығысуы (мм). Өзге нысан өшірілсе — жоспардан өзі түседі.
- Android бұл қабатты оқымайды — үйлесімділікке әсер жоқ.

## 5. Бетте көрсету

- **Сызықтар нысандардың астында**, нүктелік белгілер мен жазулар — **үстінде** (2-үлгідегідей қорғанның үстіндегі геодезиялық
  пункт көрінуі үшін). Ақ-қара басуға жарамды (горизонталь — қоңыр, ағаш — жасыл, бағдарлардың жазуы — көк, қалғаны — қара).
- Нүктелік белгінің жазуы 4 мм-ден алыс жылжытылса — сілтеме сызығы салынады (1-үлгідегі «вышка сотовой связи» сияқты).
- Ағаш терезесіз бірден сақталады, режим қосулы қалады — бірнеше ағашты қатарынан қоюға болады (Esc — аяқтау).
- Масштабты автоматты таңдау бұрынғыдай **тек нысандар мен бағыттауышқа** қарайды; жол, горизонталь сияқты ұзын сызықтар
  сызба аймағымен қиылады (SVG `clipPath`) — жоспар ұсақталып кетпейді.
- Жазулар: сызықта — бойымен (сызықтың ең түзу бөлігінде, қажет болса қайталанады), аудандарда — ортасында; бәрін алдын ала
  қарауда сүйреп жылжытуға болады (`lbl`, нөмірлердегідей).
- «Шартты белгілер» блогы бар жоспарда (қорым, 2-кезең) жағдаят түрлері де түсіндіріледі (нысан түрлерінің астында, жазудан
  басқасы). Тек қорғандары бар жоспарда блок бұрынғыдай шықпайды — белгілер үлгілердегідей жазулармен түсіндіріледі.
  Бұл — әдепкі шешім; басқаша керек болса — 7-бөлімнің 4-сұрағы.
- Жеке жоспарда да жағдаят пен өзге нысандар салынады (сол масштабта, сызба аймағымен қиылады); жазуларының ығысуы жалпы
  жоспардікі, жеке жоспарда сүйретілмейді. Біріктірілген PDF-те әр беттің қию аймағының id-і бөлек (`pj-fclip-<нысан id>`).
- Аудандар (егістік, орман, бұта, батпақ, су, құм, басқа аудан) — сызықтардың да астында; шекарасы нүктелі (су — көк, басқа аудан — тұтас),
  жазуы ортасында (ауырлық орталығы).

## 6. Кезеңдер (ұсыныс)

1. ✔ **Картада сызу (А)**: нүкте, сызық, жазу; түрлер — `tree`, `trig`, `tower`, `point`, `height`, `road`, `track`, `power`,
   `contour`, `line`, `text`; бетте салу, қию, жазуларды жылжыту; шартты белгілер. Үлгілердің ≈ 90 %-ы осымен салынады.
2. ✔ Аудандар (`arable`, `forest`, `shrub`, `swamp`, `water`, `sand`, `area`), қорғанның `surface` белгілері, қалған сызық түрлері
   (`path`, `fence`, `ditch`, `river`, `ravine`), «Өзге нысандарды жоспарға қосу» (В; маршруттар қосылмады — олар жүрген жол,
   жолдың контуры емес), жеке жоспардағы жағдаят.
3. ✔ Импорт (Г): GeoJSON / KML / KMZ / GPX → DXF → CSV / TXT нүктелер; горизонтальдарды нүктелерден құру (Д). Толығырақ — 6.1.

### 6.1. Импорт және горизонтальдар (3-кезең)

**Файлдар** («Жағдаят» → «Файлдан импорттау…»). Оқу беттің өзінде (`src/plan/importer.js`), сақтау — `fimport` (топтап, әр белгі
`cleanFeature`-пен тексеріледі, `src = import`).

| Файл | Не оқылады | Топтар |
|---|---|---|
| GeoJSON | Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon (сыртқы сақинасы), GeometryCollection; `name`, `name_ru`, биіктік (`value`, `elev`, `elevation`, `height`, `z`…), Mura `kind` | геометрия түрі не `kind` |
| KML / KMZ | Placemark: Point, LineString, Polygon (сыртқы шекарасы); `name` | геометрия түрі |
| GPX | wpt, trk/trkseg, rte | wpt / trk / rte |
| DXF (ASCII) | POINT, CIRCLE (орталығы), LINE, LWPOLYLINE (38 — биіктігі), POLYLINE/VERTEX (3D), TEXT, MTEXT; тұйық сызық — аудан; кодтауы `$DWGCODEPAGE` (ANSI_1251 → windows-1251). Бинарлы DXF және BLOCKS ішіндегілер оқылмайды | қабат (layer) |
| CSV / TXT | бөлгіш (таб, «;», «,», бос орын) мен тақырып өзі анықталады; ондық үтір; бағандарды пайдаланушы таңдайды: атауы, E, N, H, код. Тақырып жоқ болса, тахеометрдің «№ X Y H» реті (геодезиялық: X — солтүстік) болжанады | код бағаны (болса) |

Әр топқа белгі түрі таңдалады (геометриясына сай); қабат атауынан ұсынылады («Горизонтали» → горизонталь, «Пашня» → егістік,
«ЛЭП» → ЭБЖ, «Пикеты» және биіктігі бар нүктелер → биіктік белгісі т.б.). Биіктігі тұрақты сызық — горизонталь мәнімен.
2000-нан көп төбелі сызық сиретіледі (сақтау шегі).

**Координаттар жүйелері** (`src/plan/crs.js`; деректің ауқымына қарап болжанады, пайдаланушы өзгертеді):
WGS 84; UTM WGS 84 (солтүстік аймақ); СК-42 Гаусс–Крюгер (аймақ нөмірімен «10 500 000» не онсыз; Пулково → WGS 84 — Гельмерт,
`main/gpkg-read.js`-пен бірдей параметрлер, дәлдігі ≈ 1–5 м); **жергілікті жүйе** — тахеометрдің шартты координаталары: бір тірек
нүктесінің жергілікті E, N және WGS 84 орны, тордың бұрылуы (°). Әдепкіде деректің ортасы ескерткіштің негізгі координатасына қойылады —
мұндай жағдайда өзара орналасу дұрыс, абсолютті орны жуық; станцияның не белгілі нүктенің координатасын енгізу — дәлірек.
Деректің ортасы ескерткіштен 20 км-ден алыс болса — ескерту (жүйе не бағандар қате болуы мүмкін).

**Нүктелерден горизонтальдар** («Жағдаят» → «Нүктелерден горизонтальдар құру…»; `src/plan/tin.js`): ескерткіштің биіктік
белгілері (импортталған не қолмен қойылған, 3–6000 нүкте) → Делоне үшбұрыштауы (Бойер–Ватсон) → әр қима деңгейінде сызықтық
интерполяция → кесінділер сызыққа біріктіріледі → Чайкин тегістеуі (қаласа). Қима (қадамы) нүктелердің биіктік ауқымына қарап
ұсынылады. Қабырғасы шектен (әдепкіде — медианасының 4 еселігі) ұзын үшбұрыштар алынады: нүкте жоқ жерде жалған горизонталь
салынбайды. Ең төменгі және ең биік нүктенің деңгейіндегі «нүкте-горизонталь» алынбайды. Құрылған горизонтальдар `src = tin`;
қайта құрғанда ескілері ауыстырылады (қаласа). Нүктелердің өзі өшірілмейді — қажет болмаса, панельден «Барлығын өшіру».
Панельде бір түрдің белгісі 12-ден көп болса — бір жолмен (саны және «Барлығын өшіру»).

## 7. Келісуге сұрақтар және шешімдер

1. Негізгі жол — картада сызу (А), жағдаят бөлек `plan_features` қабатында — **іске асырылды** (пайдаланушы 1-кезеңді бастауды растады).
2. 3-бөлімдегі тізім — **толық қосылды**; қорғанның бетінен `trig` алынды (2-бөлімдегі ескертпе).
3. Горизонтальдар — **қолмен сызу, импорт және нүктелерден құру** (пайдаланушының шешімі, 3-кезең).
4. Шартты белгілер — блогы бар жоспарда (қорым) жағдаят та түсіндіріледі; тек қорғандары бар жоспарда — жазулармен (әдепкі шешім).
5. «Өзге нысандар» — пайдаланушы таңдағандары ғана, сілтеме арқылы; маршруттар қосылмайды (әдепкі шешім).
