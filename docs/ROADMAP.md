# Mura GIS — даму жоспары

> Бұл файл тек бағдарлама дамуының бағытын сипаттайды. Оның болуы «Жоспар», «Паспорттау» модульдерін не Mobile
> нұсқасын іске асыруға **рұқсат бермейді** — әр қадам бөлек тапсырма арқылы ғана басталады.

Mura GIS — ескерткіш туралы кеңістіктік, сипаттамалық және құжаттық ақпаратты бір жүйеге біріктіретін ГАЖ.

## 1. Модульдер мен платформалар

| # | Модуль | Desktop | Mobile | Күйі (1.2.0) |
|---|---|---|---|---|
| 1 | Ескерткіштер | ✔ | ✔ | Іске асқан |
| 2 | Маршруттар | ✔ | ✔ | Іске асқан (жол табу қоса) |
| 3 | Қорғау аймағы | ✔ | — | Іске асқан |
| 4 | Жоспар | ✔ | — | Болашақ, **әзірге жасалмайды** |
| 5 | Паспорттау | ✔ | — | Болашақ, **әзірге жасалмайды** |

Desktop: Ескерткіштер → Маршруттар → Қорғау аймағы → Жоспар → Паспорттау.
Mobile: Ескерткіштер → Маршруттар. Рет — интерфейстегі орналасу, міндетті жұмыс реті емес.
Екі платформа ортақ деректер құрылымын және үйлесімді файл пішімдерін (JSON, GeoJSON, GPX/KML/KMZ) пайдаланады.

### Модульдердің міндеттері

- **Ескерткіштер** — нүкте ретінде тіркеу, координатаны қолмен не картадан белгілеу, іздеу/сүзу/топтау, түрі мен санаты,
  импорт/экспорт, жобалар бойынша ұйымдастыру.
- **Маршруттар** — далалық маршрут құру/өңдеу, ескерткіштермен байланыстыру, қашықтық өлшеу, сақтау/импорт/экспорт.
  Бір ескерткіш бірнеше маршрутта бола алады; ескерткіш деректері көшірілмей, `id` арқылы байланысады.
- **Қорғау аймағы** — ескерткіш аумағы, қорғау аймағы, құрылыс салуды реттеу аймағы, қорғалатын табиғи ландшафт аймағы;
  геометрия, есеп, қабаттар, сақтау/экспорт. Бір не бірнеше ескерткішке байланысады; бір ескерткіштің бірнеше жоба
  нұсқасы болуы мүмкін; *жобаланған / келісуге ұсынылған / бекітілген* мәртебелері ажыратылуы тиіс.
  «Жоспар» модулімен шатастырылмайды.
- **Жоспар** (болашақ) — ескерткіштің топографиялық/археологиялық жоспары: контурлар, құрылымдар, тахеометрия импорты,
  биіктік нүктелері, горизонтальдар, қималар, шартты белгілер, масштабты жоспар, экспорт. Нақты ескерткішке байланысады,
  бір ескерткіштің бірнеше кезеңдегі жоспары болуы мүмкін.
- **Паспорттау** (болашақ) — жинақтаушы модуль: паспорт, есепке алу картасы, жоспар, қорғау аймағының сызбасы, қосымшалар
  (фото, координаталар кестесі). Деректерді басқа модульдерден алады, қолмен қайта енгізуді азайтады; құжаттың
  редакциясы, күні, бекіту мәртебесі сақталады; бекітілген үлгілер мен құқықтық талаптар ескеріледі.

## 2. Қазіргі деректер архитектурасы (1.2.0)

Барлығы — `%APPDATA%\Mura GIS\data\` ішіндегі JSON массивтер; әр модульдің өз файлы және өз `mura://app/...` протоколы
(`main/main.js`). Сақтау: `.tmp` → `rename`, алдыңғы күй `.bak`.

| Файл | Жазба | Ескерткішпен байланыс |
|---|---|---|
| `marks.json` | `{ id, name, period, oblast, district, place, type, category, status, note, lat, lon, created_*, updated_* }` | — (өзі ескерткіш) |
| `imports.json` | KML/KMZ/GPX нүктелері — «Сәйкестендіру» арқылы ғана белгіге айналады | — |
| `routes.json` | `{ id, name, a_name, b_name, note, vehicle, season, checked, pts: [[lat,lon]…], … }` | **Сақталмайды** — желі құрғанда кеңістікте есептеледі (`graph.js`, 300 м) |
| `qorgau.json` | `{ id, name, district, fields: {…}, pts: [{lat,lon}…], … }` | **Сақталмайды** — белгіден өрістер *көшіріледі* (`zone-dialog.js`) |

`id` — 16 таңбалы hex, жазба жасалғанда бір рет беріледі, өзгермейді. Бұл нұсқаулықтағы «UUID» талабын іс жүзінде
орындайды; UUID пішіміне көшу бар файлдар мен импорт тексерісін бұзады, сондықтан ұсынылмайды.

## 3. Нұсқаулықпен салыстыру: сәйкессіздіктер мен тәуекелдер

| # | Мәселе | Әсері | Ұсынылатын қауіпсіз шешім (тек тиісті тапсырма кезінде) |
|---|---|---|---|
| R1 | Қорғау аймағы ескерткішке `id` арқылы байланыспайды — атауы мен өрістері көшіріледі | Белгі өзгерсе, аймақ ескіреді; Паспорттау аймақты ескерткішке сенімді таба алмайды | `qorgau.json` жазбасына міндетті емес `mark_ids: []` өрісін қосу (`store.js` → `save()` оны сақтауы керек); `zone-dialog.js` таңдалған белгінің `id`-ін жазады. Ескі жазбалар өзгеріссіз оқылады |
| R2 | Аймақ GeoJSON-ындағы `monument_id` — шын мәнінде **аймақ жазбасының** id-і | Сыртқы жүйе/болашақ модуль оны ескерткіш id-і деп қате түсінуі мүмкін | Пішімді бұзбай, қосымша `zone_record_id` және (R1-ден кейін) `mark_ids` қасиеттерін қосу; `monument_id` үйлесімділік үшін қалады |
| R3 | Аймақ жобасының мәртебесі (жобаланған/ұсынылған/бекітілген) мен редакциясы жоқ; нұсқа — тек «Жаңа жазба ретінде сақтау» | Бекітілген шекара жобамен араласады | Міндетті емес `status` (әдепкі `draft`) өрісі; нұсқалар — бір `mark_id`-ге тиесілі бөлек жазбалар |
| R4 | Маршрут ескерткішке тек кеңістікте (300 м) байланысады | Белгі жылжыса не жақын жерде екі белгі болса — байланыс өзгереді | Сызу кезінде жабысқан белгілердің `mark_ids`-ін маршрутқа сақтау (міндетті емес); есептелетін байланыс резерв ретінде қалады |
| R5 | `clean()`/`save()` белгісіз өрістерді тастайды | Mobile не жаңа нұсқа қосқан өріс ескі Desktop-та сақтағанда жоғалады | Белгісіз өрістерді өзгертпей өткізу (қауіпсіз шектеумен), не файлға `schema` нұсқасын қосу |
| R6 | Файлдарда пішім нұсқасы жоқ (жалаң массив) | Болашақ миграцияларды анықтау қиын | Қажет болғанда ғана: массивті сақтап, `schema` нұсқасын бөлек `meta.json`-да ұстау |
| R7 | «Жобалар бойынша ұйымдастыру» жоқ | — | Ескерткіштер модулінің келесі кезеңі; жоба — ескерткіш `id`-лерінің тізімі (деректер көшірілмейді) |

R1–R5 — нұсқаулықтың «ескерткіш id — басты байланыс» талабына жақындататын шағын, кері үйлесімді түзетулер. Олар
пайдаланушы осы модульге қатысты тапсырма бергенде ғана енгізіледі.

## 4. Болашақ байланыс схемасы (логикалық)

```
Ескерткіш (marks.json, id)
 ├─ маршруттар        routes.json   → mark_ids[]          (R4)
 ├─ қорғау аймақтары  qorgau.json   → mark_ids[], status  (R1, R3)
 ├─ жоспарлар         (болашақ)     → mark_id, кезең/күні
 └─ паспорттау құжаттары (болашақ)  → mark_id, редакция, күні, мәртебесі;
                                     деректерді жоғарыдағылардан id арқылы оқиды
```

Әр модуль өз файлына ғана жазады; басқалардың деректерін оқиды. Болашақ модульдер үшін файл/кесте **алдын ала
жасалмайды**.

## 5. Үйлесімділік сұрақтары (әр жаңа функция үшін)

1. Деректер нақты ескерткішке (`id`) байланыса ала ма?
2. Кейін Паспорттау оларды пайдалана ала ма?
3. Импорт/экспорт деректі жоғалтпай ма?
4. Басқа модульдердің жұмысына әсер етпей ме?
5. Desktop ↔ Mobile деректер үйлесімділігі сақтала ма?
6. Жоспар модулін қосқанда архитектураны қайта жазу қажет болмай ма?
7. Бұрынғы жобалар мен файлдар ашыла ма?

## 6. Кезеңдер

1. **Қазір** — жұмыс істеп тұрған үш модульді дамыту, тұрақтандыру; R1–R5-ті тиісті тапсырмалармен бірге енгізу.
2. **Mobile** — Ескерткіштер мен Маршруттар, ортақ JSON/GeoJSON пішімдері, сенсорлы шағын экран.
3. **Жоспар** — бөлек тапсырма берілгенде.
4. **Паспорттау** — қалған модульдер деректері тұрақтанғаннан кейін, бөлек тапсырма берілгенде.
