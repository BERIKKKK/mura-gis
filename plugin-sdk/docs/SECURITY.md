# Плагиндердің қауіпсіздік моделі

Плагин — **сенімсіз үшінші тарап коды**. Шектеулер рұқсаттар тізімімен ғана емес, техникалық деңгейде қойылады.

## Не істелген (Mura GIS Desktop, Plugin API 1)

| Талап | Іске асуы |
|---|---|
| Жеке оқшауланған орындау ортасы | Әр плагин — жеке жасырын терезе: бөлек renderer процесі, Chromium sandbox (`sandbox: true`), `contextIsolation`, Node.js жоқ. Бағдарлама бетімен ортақ DOM, JS нысандары, localStorage жоқ |
| Негізгі контекстте орындалмайды | Плагин коды бағдарлама терезесіне ешқашан жүктелмейді. Терезеге тек сипаттама (JSON) келеді, ол `textContent` арқылы салынады |
| Рұқсатсыз деректерге қатынау жоқ | Плагиннің жеке сессиясында бағдарламаның `mura://app/` протоколы мүлде тіркелмеген; деректер тек негізгі процестегі брокер арқылы, әр шақыруда рұқсат тексеріліп беріледі |
| Файлдық жүйеге еркін қатынау жоқ | `file://` — 403; Node.js жоқ; плагин тек өз архивіндегі (хеші тіркелген) файлдарды оқиды; жазу — тек `export.saveFile` (орнын пайдаланушы таңдайды, орындалатын түрлер бұғатталған) |
| Желі — бөлек рұқсат | `network.access` жоқ болса: сессияның барлық сұранысы (fetch, XHR, WebSocket, img, beacon) `webRequest` деңгейінде тоқтатылады, прокси жоқ мекенжайға бағытталады, WebRTC UDP өшірілген, CSP `connect-src 'self'`. Рұқсат болса да — тек HTTPS / WSS |
| Жоба өзгерістері тек растаудан кейін | API 1-де жоба деректерін жазу әдісі **жоқ** (`geometry.write`, `attributes.write` сұралса да берілмейді) — плагин жобаны өзгерте алмайды |
| Қауіпті операцияға жеке ескерту | `network.access` (жоғары тәуекел) орнату кезінде әдепкі бойынша берілмейді, бөлек ескертумен көрсетіледі |
| Уақытша тоқтату | Әр плагинді өшіру; «Барлық плагиндерді уақытша тоқтату»; бағдарламаны `--no-plugins` (не `MURA_NO_PLUGINS=1`) арқылы қауіпсіз режимде іске қосу; «Процесін тоқтату» |
| Архивтің құрылымы мен тұтастығы | ZIP қатаң оқылады: «..», абсолют жол, символдық сілтеме, шифр, ZIP64, аттас файлдар, рұқсат етілмеген түрлер (бинарлы, HTML), өлшем мен сығу коэффициенті (ZIP-бомба), әр файлдың CRC-32 тексеріледі. Архивтің SHA-256 хеші көрсетіледі; орнатылған әр файлдың SHA-256 хеші сақталып, іске қосар алдында салыстырылады |
| Орнату кезінде команда орындалмайды | Орнату — тек файлдарды көшіру (уақытша қалта → `rename`). Орнату скрипттері жоқ |
| Қате бағдарламаны құлатпайды | Плагин қатесі, құлауы, шексіз циклі — тек сол процесс тоқтайды (жүрек соғысы 15 с); бағдарлама терезесі басқа процесте. 3 құлаудан кейін плагин сеанс соңына дейін тоқтатылады |
| Интерфейсті ретсіз өзгертпейді | Тек `zone.export` және `tools.menu` нүктелері; әр элемент пен терезеде плагин белгісі тұрады |

Сонымен бірге бұғатталған: `eval` / `new Function` (CSP), `window.open`, навигация, iframe, форма жіберу, жүктеу,
`alert/confirm/prompt`, камера/микрофон/геолокация/USB/Bluetooth рұқсаттары.

## Шектеулер (ашық айтылады)

* **Electron/Chromium-ға сенім.** Оқшаулау Chromium-ның renderer sandbox-ына және Electron баптауларына сүйенеді. Chromium-да
  sandbox-тан шығу осалдығы табылса, плагин одан пайдалана алады — сондықтан Electron-ды уақытында жаңарту маңызды.
* **Ресурстар.** Плагиннің жадын не процессорды жүктеуі тек «қатып қалу» деңгейінде бақыланады; жеке жад шегі қойылмаған.
* **Желі рұқсаты берілгеннен кейін** плагин оқи алатын деректерін (рұқсаттары бойынша) кез келген HTTPS серверге жібере алады.
  Сондықтан `network.access` пен `attributes.read`-ты бірге беру — сенім мәселесі.
* **Қолтаңба жоқ.** Архивтің авторын криптографиялық растау (цифрлық қолтаңба) бірінші кезеңде жасалмаған; SHA-256 тек
  тұтастықты (файл өзгермегенін) көрсетеді. Плагинді сенімді көзден алыңыз.
* **Әзірлеуші құралдары.** Пакеттелмеген (әзірлеу) режимде плагин терезесінің DevTools-ы қолжетімді; релизде өшірілген.
* `tools/run.mjs` (SDK) плагинді `node:vm` ішінде орындайды — бұл қауіпсіздік шекарасы **емес**, тек өз кодыңызды тексеруге арналған.

## Плагин авторына талаптар

1. Тек қажетті рұқсаттарды сұраңыз және `permissions.json`-да не үшін керегін түсіндіріңіз.
2. Желіні тек шынымен керек болса қолданыңыз; деректерді қайда жіберетініңізді README-де ашық жазыңыз.
3. Нормативтік есептеулерде (мыс. қорғау аймақтарының өлшемі) қолданылған құқықтық актіні және әдістемені көрсетіңіз.
4. Экспорт алдында геометрия мен атрибуттарды тексеріңіз (`geometry.validate`, `attributes.validate`).
5. Пайдаланушының деректерін өз `storage`-іңізде қажетсіз сақтамаңыз.
